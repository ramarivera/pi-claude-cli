# Legacy behavior replacement map

The integration lane owns removal of the nine legacy files below. Replacement means preserving a supported behavior or explicitly replacing an obsolete behavior required by the old architecture. This map doesn't authorize deletion before the corresponding production behavior passes its focused assertions.

| Legacy test file                | Behaviors to preserve or intentionally replace                                 | Current replacement evidence                                                                                                                                                           | Remaining gate                                |
| ------------------------------- | ------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------- |
| `tests/stream-parser.test.ts`   | JSONL fragmentation/noise/malformed input, modern envelopes                    | `tests/drivers/cli/process.test.ts` framing tests; `tests/conformance/fixtures.test.ts` `unknown-additive`, `malformed-required`                                                       | Integrated offline run                        |
| `tests/event-bridge.test.ts`    | Text/thinking/signatures, tool proposals, snapshots, stop/usage/terminal       | `tests/conformance/fixtures.test.ts` `stream-snapshot-dedup`, `snapshot-only`, `thinking-signatures`, error cases, ownership and abort cases; `tests/core/normalizer.test.ts`          | Host event projection assertions              |
| `tests/process-manager.test.ts` | Spawn/config/auth, writable stdin, abort/close/temp cleanup                    | `tests/drivers/cli/process.test.ts`; production driver conformance is the next verification task                                                                                       | Shared driver conformance                     |
| `tests/provider.test.ts`        | Provider/model registration, text/error round streams, tools, abort, sessions  | Production core/driver/host tests will replace registration and round behavior. Killing Claude at a tool boundary is intentionally superseded by a resident parked query/process       | Core plus actual adapter conformance          |
| `tests/prompt-builder.test.ts`  | Labeled history, images, assistant calls/results, continuity                   | `tests/contracts/contracts.test.ts` resume plan; replay/round behavior remains to be exercised against production core                                                                 | Production replay/continuation assertions     |
| `tests/control-handler.test.ts` | Required interaction IDs, permission replies, cancellation, malformed controls | `tests/drivers/cli/control.test.ts`; `tests/conformance/fixtures.test.ts` required tool/task IDs                                                                                       | Integrated offline run and driver correlation |
| `tests/tool-mapping.test.ts`    | Tool name/argument preservation and host inventory                             | `tests/conformance/fixtures.test.ts` `tool-ownership` preserves nested host arguments. Translating every tool to Claude built-ins is intentionally superseded by native host MCP tools | Actual host inventory/schema assertions       |
| `tests/mcp-config.test.ts`      | Advertised schemas, custom tools, private config resources                     | `tests/drivers/cli/process.test.ts` native schema/config/cleanup; SDK driver tests use public SDK MCP server seams                                                                     | Shared driver schema/cleanup conformance      |
| `tests/thinking-config.test.ts` | Supported effort/model capability behavior                                     | New entrypoint configuration and driver suites own explicit effort/capability behavior; inferred model-family effort escalation is obsolete                                            | Adapter/model capability assertions           |

These are behavioral mappings, not numerical coverage equivalence. Deterministic tests can't establish real authentication, official runtime transport compatibility, host-native tool execution or the four live combinations. Those require the separately gated real-host E2E matrix.
